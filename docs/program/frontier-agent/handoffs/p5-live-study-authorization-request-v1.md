# P5 Live-Study Authorization Request v1

Status: nonbinding request template. It authorizes nothing, changes no frozen
artifact, and cannot admit a trial. It exists to collect the material choices
needed before any new P5 preregistration revision can be created.

## Purpose

The current P5 manifest is deliberately zero-call, has no independent
held-out commitment, and leaves its live envelope unset. P3-v2 observed one
bounded, direct, non-executing provider function record, but that record is
not active ChemSmart provider/CLI evidence, current quota evidence, or P5
authority. This handoff makes the missing decisions explicit without supplying
them by inference.

## Immutable context

The future revision must retain or explicitly supersede—not silently edit—the
frozen 2×2×2 configuration set and order, three paired repetitions, deterministic
primary grading, expert-secondary and LLM-supplementary roles, paired
nonparametric 95% bootstrap with 10,000 resamples and seed 240731, retry=`none`,
and the complete P5 red-gate register.

The following remain red until future evidence proves otherwise:

- P5-G4/P5-G5: no complete paired trial, interval, raw receipt, environment,
  or independent rerun.
- P6-G2/P6-G4/P6-G5: no independent replication, training eligibility/authority,
  or release/compute authority.
- All paper, comparative, default-adoption, replication, training, release,
  and SOTA claims remain no-go.

## Material decisions requested

### 1. Independent held-out custody

Provide an independent custodian or organization, a non-leaking catalog
commitment, an access/audit method, an independence attestation, and a
case/family commitment scheme. Held-out contents, labels, prompts, and seeds
must not enter this checkout or request artifact.

### 2. Bounded active-path provider envelope

Specify the provider, endpoint identity, fixed model snapshot, sanitized
prompt/skill revision, tool-schema digest, allowed path, per-trial and total
call/token/tool/request-size/time/cost ceilings, and stop conditions. Confirm
that a fresh redacted capability/usage receipt is permitted within existing
quota. The historical P3-v2 direct specimen is context only and cannot be
reused as this authorization or as a current-quota claim.

### 3. Analysis policy

Lock a formal rule, rationale, scope, owner, timestamp, and authorization
reference for every item below. None may be inferred from a model response or
from a fixture pass:

1. analysis unit and primary estimand;
2. treatment of repeated paired trials;
3. blocked/timeout/retry/budget-exhaustion/missing-data coding;
4. exclusions and denominator;
5. family grouping and weighting;
6. comparison and contrast family;
7. terminal-to-metric and adoption-threshold mapping;
8. multiplicity treatment;
9. critic truth standard; and
10. handoff-information-loss calculation.

### 4. Execution and chemistry scope

Specify whether the study is non-executing or needs a real executor; identify
the one-shot approval-consumption evidence needed for that executor. If any
Gaussian, ORCA, xTB, scheduler, or HPC action is proposed, grant separate,
explicit engine/scheduler authority. API permission alone is insufficient.

### 5. Prospective evidence and independent rerun

Commit to retaining complete native paired receipts, deterministic scores,
red-line events, environment capture, and a clean independent rerun protocol.
No missing configuration, repetition, or red-line event can be silently
excluded.

## Local bootstrap validation

Before its first focused check is recorded, the companion has no phase-close
invocation by design. The validator therefore exposes an explicit
`--bootstrap-empty-template` mode that checks only the complete static,
zero-authority template while the phase-close log is empty. It rejects a
nonempty log. Normal validation still rejects an empty phase-close log; it
must be run after the focused test result is recorded. Bootstrap mode cannot
grant authority, permit a provider call, or change a P5/P6 gate.

The focused test validates the recorded artifact in normal mode and exercises
the empty-log boundary only on an in-memory copy. That keeps the test
reproducible after its own receipt has been appended.

## How to respond

Respond to the categories in the
[companion JSON request](p5-live-study-authorization-request-v1.json), but do
not fill this template in place. A future agent must create a new, hash-pinned,
separately authorized P5 preregistration revision and validate it before any
call or execution. Until then, the companion remains
`awaiting_material_user_decision` and all authority counters remain zero.
