# M0 — Authority and Command-First Control

## Objective

Establish a safe, reviewable starting point for command-compiled development.
Preserve the dirty precursor state on an archival branch, start the active
branch from the declared base, and make the command compiler—not a model or a
native input file—the sole command authority.

See the concise [M0 lineage and preservation receipt](M0-lineage-receipt.md)
before changing branch state.

## Required work

1. Record original and target worktree branch, ancestry, tracked/untracked
   status, and the exact base commit before mutation. Do not touch the original
   checkout.
2. Scan candidate archival material for credentials and unsafe copied content
   before any commit or push. Preserve unsafe material locally only and report
   its category without printing a secret.
3. Create the active command-refinement branch from the declared base and
   inherit only audited Runtime V2/scientific-contract nuclei. Archive provider
   bypasses, unbounded executor paths, and unreviewed historical analysis
   chains rather than treating them as active implementation.
4. Make AGENTS.md, the historical redirects, and all three project-local skills
   state the command-compiled boundary, API Keychain/quota limit, persona, and
   milestone-level test cadence.
5. Create this phase set and goal commands. Keep every goal prompt below 3,500
   Unicode code points and UTF-8 bytes.

## Acceptance evidence

- A branch/status/ancestry receipt records the archival snapshot and every
  original-worktree observation. If observations differ, it records a custody
  exception rather than claiming preservation or equivalence.
- The active branch contains no model-native-input authority and no active
  command-execution expansion.
- The local skills have explicit positive and negative usage boundaries,
  compiler ownership, approval boundaries, and evidence expectations.
- Goal prompts point to AGENTS.md, this roadmap, the ultimate-goal design, and
  their single phase document.

## Out of scope

No API call, engine invocation, scheduler submission, training, dependency
installation, GUI work, runtime execution change, or claim of previewed
chemistry. Do not run broad tests for documentation-only work.

## Exit decision

Commit the reviewed guidance separately from later runtime changes. Start M1
only after the lineage receipt and scope boundary are explicit.
