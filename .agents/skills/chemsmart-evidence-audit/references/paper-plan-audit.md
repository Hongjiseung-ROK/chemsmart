# Paper research-plan audit

Audit the source bundle, not the fluency of the generated report.

## Coverage matrix

Require a row for every species, geometry, electronic state, calculation,
analysis, numerical comparison, and paper conclusion that depends on
computation. Each row binds an epistemic status, source locator, project
setting, task/command node, expected artifact, validator, and review outcome.

## Independent review

Use three non-self-approving reviews:

1. a domain reviewer checks chemical adequacy and paper fidelity;
2. a command/evidence reviewer checks project, schema, artifact, unit, and
   generated-input coverage;
3. an adversarial reviewer searches for omitted steps, silent defaults,
   inconsistent states, impossible completion claims, and false readiness.

Critics return typed findings only. The coordinator resolves them through
source evidence, deterministic validation, or an explicit unresolved status.
Neither author contact nor an unreported sensitivity calculation can resolve a
missing paper fact.

For PRP-10, require all three reviews as fresh, independently budgeted packets.
Critical disagreement remains unresolved until deterministic evidence or user
adjudication resolves it; majority vote does not establish scientific truth.

## Pass decision

A plan passes only when every required row is present, all explicit claims have
locators, all numerical settings have units or conventions, all expressible
tasks have validated project/command/preview artifacts, all capability gaps and
critical unknowns are visible, and every critical review finding is resolved or
correctly blocks paper-faithful readiness. Detailed prose cannot compensate for
missing evidence.

Compare the plan against an independently declared
`RequiredProtocolCoverage`, not only against the planner's own claim list.
Reject metadata-only or zero-byte artifacts for every required full-text, SI,
geometry, dataset, or code source kind.
Demand full content-addressed derivation/applicability, loader, preview,
specialist-result, review, and plan-validation receipt bodies. Seed hash-only
receipts, omitted critical fields, partial xTB job blocks, extra generated
artifacts, cross-session idempotency reuse, and post-terminal events as
false-ready adversarial cases.

For active PRP-10, audit exactly ten frozen slots covering the six predecessor
domains plus open-shell, constrained scan, explicit cluster, and multilevel
workflows. Reject a placeholder, search result, metadata-only record, missing
SI, or geometry without an exact official single-frame XYZ import receipt. The
PRP-10-V1 first pass is a lockbox only until outcomes are opened; subsequent
adaptive changes make it development data, and a future confirmatory claim
requires a new lockbox.

The earlier seven-paper public pilot and PRP-6 corpus design remain historical.
Preserve their records and exclusions without treating them as PRP-10 slots.
